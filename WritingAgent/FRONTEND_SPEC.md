## 1. 核心概念

### 1.1 剧院隐喻

整个系统围绕**剧院隐喻**构建，每个页面是一个独立的空间，有各自的氛围和交互节奏：

| 空间 | 路径 | 用途 | 氛围 |
|------|------|------|------|
| 剧院大厅 | `/` | 场景列表、最近活动 | 导览、概览 |
| 观众席 | `/stage/<id>/watch` | 实时观看角色互动 | 沉浸、观察 |
| 后台 | `/stage/<id>/setup` | 搭场景、审阅剧本 | 创作、讨论 |
| 休息室 | `/chat/<char-id>` | 聊天、日记、记忆整理 | 随意、私密 |

### 1.2 核心设计原则

- **全知读者**：用户（作者）可以同时看到所有角色的内部状态和对外表现，享受"角色之间不知道彼此内心"的信息差带来的叙事张力。
- **剧院感**：内容即界面。导航和 chrome 默认隐藏，只在需要时出现。
- **桌面优先**：三栏/浮动面板布局至少需要 1400px 宽屏。不支持移动端。
- **三个独立视图**：观众席、舞台监督、角色控制台是三种完全不同的心智模式，各自独立渲染，通过 URL 路由切换。

## 2. URL 结构与路由

```
/                             → 场景画廊（剧院大厅）
                                 重定向到 /scenes 或显示场景列表

/stage/<sceneId>/watch        → 观众席
                                 参数：sceneId（场景唯一标识）

/stage/<sceneId>/setup        → 舞台监督
                                 参数：sceneId（场景唯一标识）

/chat/<characterId>           → 角色控制台
                                 参数：characterId（角色唯一标识）
                                 查询参数：?tab=chat|diary|audit

/chat/<characterId>/diary     → 角色控制台 - 日记
/chat/<characterId>/audit     → 角色控制台 - 记忆整理
```

路由设计说明：
- 观众席和舞台监督共享场景上下文，放在 `/stage/<sceneId>/` 下，体现层级关系
- 角色控制台独立，因为角色跨场景存在
- 不使用平级 Tab 切换，三个视图的切换是低频的、有意向的跳转

## 3. 全局 UI 外壳

### 3.1 设计哲学：剧院

- **导航栏默认隐藏**。鼠标移动到屏幕顶部边缘时，导航栏从顶部滑出。
- **导航栏包含**：
  - 左侧：站点 Logo / "独立角色舞台" 文字标志
  - 中部：当前正在运行的场景指示器（"场景 #18 运行中 ⏵"），可点击快速跳转到观众席
  - 右侧：通知铃铛（未读重大事件数量）、快捷入口（回到当前活跃场景）
- **导航栏是半透明毛玻璃效果**，不遮挡内容。
- **每个页面有自身的氛围/背景**，不共享统一的页面背景色。

### 3.2 通知系统

后端通过 WebSocket 推送两类通知：

| 通知等级 | 触发条件 | 表现 |
|----------|----------|------|
| 场景结束 | 场景自然结束或被手动结束 | 导航栏铃铛闪烁 + 桌面 Notification API 推送（如果浏览器允许） |
| 重大事件 | 角色情绪阈值触发 / 关键记忆回溯 / 话题重大转折 | 导航栏铃铛角标数字 +1 + 桌面通知（可选） |

用户点击铃铛展开通知列表，显示近期事件的时间线摘要，点击跳转到对应场景/时刻。

### 3.3 全局主题

- 深色主题（默认），配合叙事氛围
- 字体：等宽字体用于系统/记忆信息，衬线/无衬线字体用于角色对白和叙事文本
- 角色色板：每个角色自动分配一个主题色，全局一致（中栏卡片、浮动面板、时间轴轨）

## 4. 场景画廊（首页）

### 4.1 路由

`GET /`

### 4.2 页面描述

场景画廊是系统的首页，以卡片网格展示所有场景（包括进行中和已归档的）。它相当于"剧院大厅"——用户在这里选择"看哪场戏"。

### 4.3 组件规格

#### 场景卡片

| 字段 | 类型 | 说明 |
|------|------|------|
| 场景名称 | string | 用户命名的场景标题 |
| 状态 | enum | `running` / `ended` / `draft` |
| 参与角色 | array<CharacterInfo> | 角色头像 + 名称（最多显示 4 个，超出显示 +N） |
| 交互轮次 | number | GM + 所有角色的消息总数 |
| 持续时间 | string | "43 分钟" / "2 小时 15 分钟" |
| 最后活动 | string | 相对时间，"2 分钟前" / "昨天" |
| 场景描述 | string | 一两句话概括场景设定 |
| 是否有未读重大事件 | boolean | 徽章提示 |

**卡片交互**：
- 点击卡片 → 进入该场景的观众席 `/stage/<id>/watch`
- 右键/长按 → 快捷菜单："进入舞台监督"、"归档"、"删除"

**状态特殊表现**：
- `running`：卡片有呼吸灯动画，边框微光
- `ended`：卡片常规静态
- `draft`：卡片灰阶/虚线边框，标记"草稿"

#### 页面布局

- 顶部：标题 "舞台" + 创建新场景按钮
- 下方：按最后活动时间倒序排列的卡片网格
- 空状态：无场景时显示引导文字 + "创建第一个场景"按钮

## 5. 观众席

### 5.1 路由

`GET /stage/<sceneId>/watch`

### 5.2 页面描述

观众席是系统的核心视图。用户在实时观看多角色互动时处于此页面。布局是**全宽中栏 + 浮动仪表盘面板**——没有固定左右栏。

### 5.3 布局结构

```
┌─────────────────────────────────────────────────────┐
│ ─── 顶部演员表手柄（最小化）                         │
│                                                       │
│  中栏：活动流（全宽）                                 │
│  ┌─────────────────────────────────────────────┐     │
│  │ [GM 🎭] 雨停了，窗外的路灯开始亮起...      │     │
│  │ [A    💬] "你看到那个邮件了吗"              │     │
│  │ [B    💬] "嗯。"                            │     │
│  │ [A    🏃] A 从电脑前抬起头...               │     │
│  │ [GM 🎭] 咖啡机发出咕噜声...                │     │
│  └─────────────────────────────────────────────┘     │
│                                                       │
│ ─── 底部时间轴                                       │
│ [◀‖  ═══■══════════■══■═══════════════ ■■══▶ ]    │
│                                                       │
│ 浮动：A 的仪表盘 (悬停/点击展开)                      │
│ ┌──────────┐                                         │
│ │ 😊 平静  │                                         │
│ │ 🧠 "她在 │                                         │
│ │    回避我"│                                         │
│ │ 📖 recall│                                         │
│ └──────────┘                                         │
└─────────────────────────────────────────────────────┘
```

### 5.4 组件规格

#### 5.4.1 中栏：活动流

**卡片类型与视觉区分**

| 卡片类型 | 徽章 | 底色 | 内容 |
|----------|------|------|------|
| GM 环境旁白 | `🎭 环境` | 灰色半透明 | 场景描写、天气、光线、声音、气味 |
| GM 扮演 NPC | `🎭 NPC` | 灰色半透明（加深） | NPC 的对话和动作 |
| 角色对外行动 | `💬` 或 `🏃` | 角色主题色（浅） | 台词、动作描述 |
| 角色位置切换 | `🎬 场景` | 暗金色 | GM 切换场景/推进时间 |

**卡片结构**（以角色对外行动为例）：
```
┌──────────────────────────────────────────────┐
│ [头像] [角色名] [💬 对话]  [17:23:45]        │
│                                               │
│ "那句台词本身——"他顿了顿，"没什么。"         │
│                                               │
│ [内心独白预览] [↗]                           │
└──────────────────────────────────────────────┘
```

- 左上角：角色头像（圆形）+ 名称 + 消息类型徽章 + 时间戳
- 中部：消息正文（台词用引号，动作用斜体/叙述体）
- 右下角（可选）：内心独白预览入口（如果该卡片涉及角色对外行动，而同一时刻有内心独白，显示一个"内心"按钮）

**内心独白预览按钮**：点击后在当前位置展开一个嵌入式浮层，显示该角色在说出/做出这个行动时的内部思考。这个浮层有角色主题色左边框。关闭后折叠。

**消息顺序**：严格按时间升序。GM 消息、角色消息交叉出现。

**自动滚动**：新消息到达时，如果用户已滚动查看历史，不自动跳转到底部（尊重用户的阅读位置）。显示一个"↓ 回到最新"浮动按钮。

#### 5.4.2 浮动仪表盘面板

**触发方式**：
- 鼠标悬停在活动流中某个角色头像/名字上 → 浮层面板展开（延迟 300ms）
- 鼠标移出浮层面板 → 浮层收起（延迟 500ms）
- 点击浮层面板右上角的 pin 图标 → 面板固定，不随鼠标移出收起
- 再次点击 pin → 解除固定

**面板位置**：浮动在活动流上方，优先在触发点的右侧/左侧展开，避免遮挡触发点附近的上下文。

**面板内容**：

| 区域 | 内容 |
|------|------|
| 顶部 | 角色头像 + 名称 + 情绪标签（😊 平静 / 😠 烦躁 / 🤔 犹豫） |
| 主体 | 最近一条内心独白（"她是不是在回避我……"） |
| 附加 | 最近一次记忆活动（📖 recall: "想起上次在茶水间……" / ✏️ memorize: "记下：他今天穿了件深蓝色卫衣"） |
| 底部 | 快捷操作按钮：「聚焦此角色」「跳转到此角色最近活动」|

**面板大小**：宽度 320px，高度随内容自适应（最大 400px），超出可滚动。

**允许多个面板同时打开 pin 住**，但建议不超过 3 个，避免遮挡过多活动流。

#### 5.4.3 演员表

**触发方式**：屏幕右侧边缘有一个窄手柄标签 `🎭 演员表 (N人)`。
- 点击 → 从右侧滑出演员表面板（覆盖在中栏上方，半透明背景遮罩）
- 再次点击或在遮罩区域点击 → 关闭
- 关闭后 3 秒无操作，手柄自动半透明隐藏；鼠标移至右侧边缘重新显现

**面板内容**：当前场景所有出场角色的列表，每个条目显示：
- 头像 + 名称 + 最近一条对话/动作摘要
- 角色状态指示器（活跃/沉默/离线）
- 点击条目 → 关闭演员表面板，触发该角色的浮空仪表盘展开

#### 5.4.4 时间轴

**位置**：屏幕底部，固定定位（sticky bottom）

**组成**：
- **多轨活动带**：每个角色 + GM 各占一条彩色横轨。轨上有活动标记（竖线/点），表示该角色在该时刻有行动。空白表示沉默/等待。
- **主拖拽条**：横跨整个时间轴的一个拖拽手柄，拖动跳转到对应时刻
- **播放控制**：左侧有「回到最新」按钮（■ 停止/▶ 播放）
- **缩放控制**：右侧有「+ -」缩放按钮，改变时间轴的时间跨度（5分钟/15分钟/30分钟/全部）

**标记交互**：
- 鼠标悬停在某个标记点上 → 显示该时刻的摘要 tooltip
- 点击标记点 → 活动流滚动到对应位置，高亮该卡片

**初始状态**：
- 首次加载时，时间轴最小化（折叠成一条细线显示"活动概览"），用户可拖拽展开
- 如果场景仍在运行，时间轴默认显示最近 5 分钟的活动

#### 5.4.5 加载态（叙事开场白）

**加载状态流程**：

1. 用户进入 `/stage/<id>/watch`
2. 页面骨架渲染（三栏占位 → 实际为全宽中栏占位 + 浮动栏占位 + 底部时间轴占位）
3. 加载场景元数据的同时，屏幕中央淡入**场景序幕**
4. 序幕是一个精美的文字卡片，居中显示，内容类似：
   > **场景 #18：午后的茶水间**
   >
   > 2024 年 6 月 17 日，下午两点。雨刚刚停。
   >
   > 茶水间的窗开着一条缝，风带着湿气吹进来。咖啡机咕噜咕噜地响着。
   >
   > A 靠在料理台边上，手里捏着一支笔，没在写什么。
   >
   > B 从走廊那头走过来，脚步声在瓷砖上很清晰。
5. 数据加载完成后，序幕淡出，中栏、时间轴、浮动面板等正式界面淡入
6. 如果场景已有历史记录，中栏从第一条活动消息开始展示；同时页面顶部短暂显示"此前已有 XX 轮互动"标签

**如果场景已在运行中（有 WebSocket 推送）**：序幕显示"正在直播中"标记。

#### 5.4.6 补课模式

用户离开后回来或有历史记录的场景，显示**场景摘要弹窗**：

```
┌────────────────────────────────────────────┐
│ 📋 截至目前剧情摘要                        │
│                                            │
│ A 和 B 就项目 deadline 发生了分歧。        │
│ A 试图缓和气氛但 B 没接话。               │
│ A 回忆起上次类似的情况，内心有些不安。     │
│ 目前两人陷入沉默。                        │
│                                            │
│ [进入现场]  [查看完整记录]  [关闭]         │
└────────────────────────────────────────────┘
```

- "进入现场"：关闭弹窗，滚动到最新位置
- "查看完整记录"：关闭弹窗，滚动到场景第一条消息
- "关闭"：关闭弹窗，保持当前阅读位置

此弹窗仅对"有历史记录的非实时场景"或"人离开后新产生了大量消息"时展示。实时观看中不弹。

### 5.5 WebSocket 事件处理

| 事件类型 | 前端行为 |
|----------|----------|
| `scene:message` | 新消息到达，追加到中栏活动流 |
| `scene:state_change` | 更新通知铃铛 |
| `scene:character_internal` | 更新对应角色的内部状态缓存（不自动显示，等用户触发浮动面板时展示最新状态） |
| `scene:milestone` | 触发通知，时间轴上标记重要节点 |
| `scene:ended` | 触发场景结束通知，观众席进入"已结束"状态（活动流只读，显示结束横幅） |
| `scene:summary_ready` | 场景结束/AI 生成了新阶段摘要，展示摘要弹窗（仅当用户处于非活跃状态后首次回到页面时） |

## 6. 舞台监督

### 6.1 路由

`GET /stage/<sceneId>/setup`

### 6.2 页面描述

舞台监督是"后台"。用户的角色不是填表配置，而是和"编剧 Agent"对话讨论场景方向，审阅成稿，定稿后启动。

### 6.3 布局

```
┌─────────────────────────────────────────────────────┐
│  ← 返回场景画廊                                     │
│  场景名称：[午后的茶水间           ] [💾 保存]     │
│                                                       │
│ ┌───────────────────┐  ┌───────────────────────────┐ │
│ │   编剧对话区       │  │   场景文档预览区           │ │
│ │                    │  │                           │ │
│ │ [对话气泡]         │  │ # 场景：午后的茶水间      │ │
│ │ [对话气泡]         │  │                           │ │
│ │ [对话气泡]         │  │ ## 基本信息               │ │
│ │                    │  │ 时间: 2024.6.17 14:00    │ │
│ │ [输入框]           │  │ 地点: 茶水间              │ │
│ │                    │  │ 角色: A, B               │ │
│ └───────────────────┘  │                           │ │
│                         │ ## 初始状态              │ │
│ [📋 生成草稿]           │ A 靠在料理台边上...       │ │
│ [🎬 开演 →]             │                           │ │
└─────────────────────────────────────────────────────┘
```

### 6.4 组件规格

#### 编剧对话区（左侧）

- 类似即时消息界面，用户和"编剧 Agent"之间对话
- 用户输入自然语言意图（"我想让 A 和 B 在茶水间偶遇，气氛有点尴尬"）
- Agent 回复结构化的场景提案、问题、建议
- 每条 Agent 回复右上角有「应用到文档」按钮，点击后将回复中的场景设定填充到右侧文档预览区

#### 场景文档预览区（右侧）

- 展示当前草稿的结构化场景文档
- 文档内容包含：基本信息、角色初始状态、场景气氛、背景提要、剧本方向
- 用户可以直接在文档上做行内批注/修改（contenteditable 或类似机制）
- 修改后自动标记"未审阅"状态

#### 操作按钮

| 按钮 | 行为 |
|------|------|
| 📋 生成草稿 | 将编剧对话区的讨论内容发送给 Agent，生成结构化场景文档填入预览区 |
| 🎬 开演 | 定稿，将场景文档推送给 GM Agent 和角色，启动场景。按钮变为「⏳ 演出中…」，完成后跳转到 `/stage/<id>/watch` |

## 7. 角色控制台

### 7.1 路由

`GET /chat/<characterId>`
`GET /chat/<characterId>/diary`
`GET /chat/<characterId>/audit`

### 7.2 页面描述

角色控制台是"休息室"——用户以朋友/同事身份和角色聊天、阅读角色的日记、帮角色整理记忆。在这里，角色可能知道用户是"作者"（第四面墙打开），也可能不知道（第四面墙关闭），由用户切换。

### 7.3 布局

```
┌─────────────────────────────────────────────────────┐
│ [角色列表]  │ [聊天/日记/记忆  Tab]                  │
│              │                                       │
│ ┌───────┐    │ ┌───────────────────────────────┐     │
│ │ 头像A  │    │ │ [聊天] [日记] [记忆整理]      │     │
│ │ A 名称 │    │ │                                │     │
│ │ 最后   │    │ │ [消息气泡]                     │     │
│ │ 消息   │    │ │ [消息气泡]                     │     │
│ │        │    │ │ [消息气泡]                     │     │
│ │ 头像B  │    │ │                                │     │
│ │ B 名称 │    │ │ [输入框]       [🎭 4th Wall]  │     │
│ │ 最后   │    │ └───────────────────────────────┘     │
│ │ 消息   │    │                                       │
│ └───────┘    └───────────────────────────────────────┘
```

### 7.4 组件规格

#### 角色列表（左侧栏）

- 固定宽度 280px
- 角色条目：头像 + 名称 + 最近一条消息预览（截断到一行）
- 角色条目按最近对话时间倒序排列
- 当前选中的角色高亮

#### Tab：聊天

**与角色聊天界面**。

- 消息以气泡形式展示，角色气泡以角色主题色左边框/气泡色，用户气泡以灰色
- 输入框在底部
- 输入框右上方有一个**第四面墙开关**（`🎭 4th Wall` 按钮）：
  - 开（默认）：角色知道自己在和"作者"聊天。提示词注入"你可以和创造你的人直接对话"。
  - 关：角色不知道自己在一个系统中。用户需要以叙事方式进入角色世界（例如以一个新同事/朋友的身份发消息）。
  - 开关切换不影响聊天历史，只影响下一条消息的提示词上下文。
- 用户发送消息后，角色响应通过 WebSocket 流式返回。显示打字指示器。

#### Tab：日记

**阅读角色的日记条目**。

- 按时间倒序排列的日记卡片列表（没有分页，懒加载滚动）
- 每条日记卡片显示：
  - 日期 + 场景关联（"来自场景 #18：午后的茶水间"）
  - 日记正文（第一人称，自由文体）
  - 字数统计
- 日记由系统在场景结束后自动触发生成，用户不可在此编辑
- 用户可以对日记条目做「标记为重要」/「添加注释」

#### Tab：记忆整理

**查看和帮助角色管理记忆**。

**主交互方式：对话式整理**（Tab 默认视图）。

- 这是一个特殊的聊天界面——用户的对话对象是该角色的"记忆系统"（或以角色自身的"思考"形式呈现）
- 角色以自然语言"思考"自己的记忆：
  > 「我记得上次和 B 在茶水间聊过 deadline……但那个印象好像已经不太准确了，我应该更新一下。」
- 用户回应该思考，触发更新操作（"你觉得哪里不准确？" → 角色给出修正 → 用户确认 → 写入记忆系统）
- 每次确认变更时，底部出现操作反馈条：「已更新记忆条目 #42」

**次级交互方式：列表视图**（右上角切换按钮）。

- 以结构化列表展示所有记忆条目
- 每个条目显示：
  - 时间戳
  - 内容摘要（第一人称）
  - 触发条件/标签
  - 重要性（⭐ 1-5）
- 行内操作：编辑、删除、合并（拖拽到另一个条目上）、调整重要性
- 批量操作：多选后批量删除/归档

## 8. 交互范式详述

### 8.1 角色色板系统

每个角色在创建时自动分配一个主题色（基于名称哈希或手动设置）。
色板用于：
- 中栏卡片的角色消息底色（半透明）
- 浮动仪表盘面板的强调色（边框/标题）
- 时间轴上该角色的活动轨颜色
- 角色控制台中角色气泡的颜色

色板从预设的色板池中分配（12-16 种高辨识度颜色），避免冲突。GM 统一使用灰色。

### 8.2 内心独白的分层展示

角色在行动时同时有内心独白，但对外表现和内心思考是分开的。

中栏活动流**默认只显示对外表现**（对话、动作）。内心独白通过两个入口查看：
1. **浮动仪表盘**：面板主体区域显示最近的内心独白
2. **活动流卡片扩展**：点击卡片右下角的内心图标（💭）展开内嵌浮层，显示该时刻的完整内心活动

用户不需要切换模式即可"选择性地"查看内心——想深入就看，想保持表面就不展开。

### 8.3 跨页面的场景上下文

观众席和舞台监督共享场景 ID。当用户在舞台监督中点击"开演"后，自动跳转到该场景的观众席。导航栏始终显示"当前活跃场景"的入口。

角色控制台独立，因为角色跨场景存在。

### 8.4 异常状态

| 状态 | 处理 |
|------|------|
| 场景不存在（404） | 显示"这个舞台不存在"，提供返回场景画廊的链接 |
| 角色不存在（404） | 显示"休息室里没有这个人" |
| WebSocket 断线 | 中栏顶部显示黄色警示条「连接已断开，正在重连…」，重连后自动拉取断线期间的消息并追加 |
| 场景上下文加载失败 | 显示错误提示 + 重试按钮，保留序幕/开场白氛围 |
| 空场景（无历史消息） | 中栏显示「舞台空无一人，等待开场…」留白状态 |

## 9. 数据契约

### 9.1 API 端点

```
GET    /api/scenes                        → 场景列表
GET    /api/scenes/:sceneId               → 场景详情
GET    /api/scenes/:sceneId/timeline      → 场景完整时间线
GET    /api/scenes/:sceneId/characters    → 场景演员表
GET    /api/scenes/:sceneId/state         → 场景当前最新状态快照
GET    /api/scenes/:sceneId/summary       → 场景阶段摘要

GET    /api/characters                    → 角色列表
GET    /api/characters/:characterId       → 角色信息
GET    /api/characters/:characterId/diaries  → 角色日记列表
GET    /api/characters/:characterId/memories → 角色记忆列表

WS     /ws/scenes/:sceneId                → WebSocket 连接（场景实时推送）
WS     /ws/chat/:characterId              → WebSocket 连接（Chat 模式消息流）
```

## 10. 技术选型建议

### 10.1 前端框架

**推荐：React + TypeScript**

原因：
- 组件化程度高，适合三视图独立开发
- 生态成熟（路由、状态管理、WebSocket、动画）
- 团队/社区资源多

### 10.2 路由

**React Router v6**

- 支持嵌套路由（`/stage/:id/setup` 和 `/stage/:id/watch` 共享前缀）
- 支持 loader 数据预加载

### 10.3 状态管理

**推荐 Zustand**（轻量）或 **Jotai**（原子化）

原因：
- 不需要 Redux 的仪式感
- WebSocket 推送更新 + 多视图共享角色状态需要全局 store
- Zustand 的 subscribe 模式适合 WebSocket 推送场景

### 10.4 WebSocket

**原生 WebSocket API + 重连封装** 或 **Socket.io**（如果后端也用它）

### 10.5 UI 组件库

**不推荐大型组件库**（Ant Design / Material UI），原因：
- 剧院感/沉浸感需要高度定制化 UI
- 卡片流、浮动面板、时间轴等组件是定制的

推荐：
- **Tailwind CSS** + **Radix UI**（无样式原子组件：Popover、Tooltip、Dialog）
- 自己构建设计系统（角色色板、消息卡片、浮动面板）

### 10.6 动画

**Framer Motion**

- 消息进入/离开动画
- 浮动面板展开/收起动画
- 导航栏滑入/滑出
- 场景序幕淡入淡出

### 10.7 Mock 数据

**MSW (Mock Service Worker)** 或简单静态 JSON

- MSW 拦截请求，在前端 worker 层返回 mock 数据
- 或者直接在后端 API 调用处返回硬编码 JSON
